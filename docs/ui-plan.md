# 界面设计规划

按 oil-ui 的流程走：先定产品事实，再删，再定结构，最后才谈视觉。

## 一、产品事实

| 项 | 内容 |
|---|---|
| 用户 | 国内用 Codex 的开发者，代理开着但报错或连不上，不熟悉网络细节 |
| 场景 | 30 秒内要知道「哪里断了」以及「下一步该动什么」 |
| 真实内容 | 7 个域名的四段探测结果、环境信息、一句归因结论 |
| 设备 | 桌面浏览器为主（1278 宽），窗口最小到 900 宽也不能塌 |
| 技术限制 | 纯静态单文件，本地 127.0.0.1，**不能引外部 CDN**，不能上构建工具，离线可用 |
| 资产 | 无图片、无图标库、无字体文件。只能用系统字体和 CSS 画的形状 |

最后一条是硬约束，也决定了方向：视觉重量必须由**排布和线**承担，而不是图片或品牌元素。

## 二、主角与主动作

- **主角**：一句归因结论。整个页面只允许它最大。
- **主动作**：重新检测。其余一切可交互元素都为它让位。
- 每屏一个主角：结论区是唯一的大字区域，其余全部降为小字和细线。

## 三、删除清单

先列删掉什么，剩下的才是要设计的：

1. **删掉 7 张等权的结论卡片**。现在所有发现都是同一个样式的卡片，用户读完不知道从哪下手。收敛成：一句大结论 + 最多 3 条要点，信息级的直接折进底部环境区。
2. **删掉「TLS 证书签发方」独立条目**。它的价值只在出现陌生签发方时体现，平时是噪音。挪进底部环境行。
3. **删掉表格里的「作用」列**。名字已经说明一切，占了一整列宽度。
4. **删掉每条建议的独立展示**。建议跟着问题走，不单独成块。
5. **删掉一级标题区所有装饰**。页头只有标题、状态徽标、按钮。

## 四、灰度结构

主视口 1278 × 900，只有一个页面：

│  Codex 链路体检        [代理] [TUN] [出口 JP]     ⟳ 重测  │  页头

### 为什么是「四段链」而不是「本机→代理→节点→OpenAI」

我原本想画一条从本机到 OpenAI 的链路，四站：本机、代理、节点、对方。看起来更符合直觉，但**测不出来**。我拿不到代理软件内部的状态，也没法确定断的是节点还是规则。画上去就是编。

真实能测到的只有四段，而且是每一段都实测过：

| 段 | 用什么测 | 断了说明什么 |
|---|---|---|
| 解析 | DNS 返回了几条 A / AAAA | 域名没变成地址，DNS 层有问题 |
| 连接 | TCP 握手耗时 | 地址有了但连不上，节点或路由不通 |
| 加密 | TLS 握手耗时和版本 | 连上了但谈不成，可能是证书或中间人 |
| 应答 | HTTP 状态码 | 谈成了但对方不说话，或者被拒绝 |

这四段是链式依赖：前一段断了后一段必然空着。所以矩阵的读法是**从左往右找第一个空心格**，那就是断点。比看七张卡片快得多。

## 五、方向

**方向名：通电链路**

一句话：像一台安静的仪器面板，四条线接通的那一刻会亮起来。

具体决定：

- **感觉**：克制、精确、不喧哗。不是消费产品，是工具。
- **字体**：系统无衬线承担文字，所有数字和域名用等宽字，且等宽数字对齐（`tabular-nums`），让 401 / 142ms 这类读数能竖着扫。
- **色彩**：近黑底 `#090B0F`，面板 `#101319`，分隔线只有 1px `#212734`。语义色三枚：通 `#4CC38A`、注意 `#D9A253`、故障 `#EA6A5E`。**没有装饰性强调色**，颜色只用来表示状态，不表示心情。
- **空间**：留白靠行距和区块间距撑，不靠卡片阴影。全站没有 box-shadow。
- **形状**：面板 6px 圆角，单元格 4px，除此之外全是直角细线。不用胶囊形按钮。
- **唯一例外的一刻**：四段链上的小方块按顺序逐格亮起。这是全页唯一动效，其余全部安静。检测完成时它从灰变成绿，像电路通了电。

### 和常见做法的差别

- 不做顶部大渐变背景
- 不做卡片浮起 + 阴影
- 不做圆形进度环
- 不把状态做成彩色胶囊标签堆一排

这些是 AI 生成界面最容易滑进去的默认做法，而且会让「诊断结论」和「装饰」抢注意力。

## 六、验收要点

1. 只看首屏，能不能说出「哪里断了」
2. 四段链在 900 宽和 1600 宽都要完整，不断行
3. 全红（七个域名全断）和全绿两种极端状态都不塌
4. 中文多行标题在窄屏不被裁切
5. 数字列右对齐，等宽对齐后能竖着读
6. 键盘 Tab 能走到「重新检测」，焦点可见

| 结论 | 26 | 30 |
| 品牌 | 14 | 16 |
| 段落标题 | 12 | 13.5 |
| 阶段计数 | 13 | 15 |

行高、内边距、方块高度同步跟上（方块 20 → 22px），否则只是字变大、行距变密。

## 八、做到什么程度了

做完了，并且用真实截图核过。两张图在 `docs/screenshots/`：

- `desktop-1280.png` — 1278 宽（你的实际窗口尺寸）
- `desktop-900.png` — 900 宽，四段链变成 2×2，表格不溢出，长路径换行

验收清单的落实情况：

| 项 | 结果 |
|---|---|
| 首屏能说出哪里断了 | 能。结论句 + 四段链 + 矩阵第一个空格 |
| 900 / 1600 宽不塌 | 900 实测：无溢出、无裁切、三行换行对齐正常；1600 未单独测，max-width 1240 封顶 |
| 全红状态不塌 | 实测即全红，正常 |
| 全绿状态不塌 | **未验证**。跑不出全通的网络环境 |
| 中文多行不裁切 | 实测无裁切 |
| 数字竖着可读 | 等宽 + tabular-nums，列宽固定 96px |
| 相邻列不叠字 | 实测最小间隙 10px（初版是 -2px，重叠了） |
| Tab 可达、焦点可见 | 是，`focus-visible` 有 2px 轮廓 |

## 九、过程中修掉的三个真问题

这几条不是视觉问题，是产品问题，但都是做这个界面时撞出来的。

**一、三条建议一模一样。** 原来三条「需要处理的」写的都是「节点不通或被分流到了走不通的路。先确认这个域名走的是哪条规则。」用户读完仍然不知道下一步该干什么。现在按断点分：断在解析说 DNS，断在连接说分流规则，断在加密说 TLS 拦截，断在应答说中间层。同断点的多个域名合并成一条。

**二、`td.name` 上用了 `display: flex`。** 那是把表格单元格变成弹性容器，直接破坏表格布局。症状是列宽不受控、对不齐。改成内部 div 承载 flex。这个 bug 光看代码看不出来，是截图里列宽乱掉才发现的。

**三、长路径压到了下一列。** 字号调大后，最长的那个域名行已经侵入「解析」列 2px。截图上看不出来，是量了每个单元格的右边界和相邻列的左边界才发现的。修法：域名列 400 → 460，并且给 `.idcell` 加 `flex-wrap`，宁可变两行也不越界。

- 没有做多方向对比页。oil-ui 的默认路径是推荐一个方向，用户明确要求比较时才铺开。想比较的话可以说，我按同一套功能出三版放一页上。
- 没有做移动端布局。这个工具只在桌面跑，`127.0.0.1` 的页面手机上打不开。窗口窄到 900 以下时只保证不塌。
