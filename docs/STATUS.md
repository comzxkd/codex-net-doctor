## 这一版做了什么

### 零、先修了个假启动

`start.bat` 第一版双击没反应。两个原因叠在一起：

- 文件是 LF 行尾，而 `cmd.exe` 要 CRLF。它把行切错了位置，`py run.py` 被
  截成 `n.py`，报 `'n.py' is not recognized`。
- 批处理里写了中文，配上代码页不匹配，进一步把行切乱。

改成 CRLF + 纯 ASCII 后实测通过：服务监听 8787，首页返回 200，
`/api/progress` 返回 `{"running": true, "done": 1, "total": 5}`。
代价是控制台提示变成了英文。考虑到就四行字，而且中文提示写在网页里，
可靠性优先。

顺手把端口占用时的报错改成人话，不再是一条 traceback。

### 一、结论从「检查项」改成「能不能用」

原来顶部写「关键检查项里有 4 个走不通」，用户看完还是不知道自己能不能干活。
现在直接说「Codex 现在用不了：账号登录和 API Key 两条路都断了」。

实现上靠 `core` 标记：只有真正决定产品能不能用的地址才算数，
`cdn-cgi/trace` 这类只是体温计，不是病人必需。

### 二、两种接入方式各自判定

账号登录靠 `chatgpt.com/backend-api/codex/responses` 和 `auth.openai.com`；
API Key 靠 `api.openai.com/v1/models`。哪条断了就直接说卡在哪。

这样能回答「我一不能用是不是还有另一种能用」这个实际问题。

### 三、每个地址标上作用

用户提的第二个困惑是「这些地址是什么意思」。矩阵每行加一行小字，
复用已有的 `role` 字段。行高从 53 涨到 75。

### 四、start.bat

双击就能启动。原因见上面那条「本机跑出来的结论不能当真」：
必须由用户自己的终端启动，不能由别的程序代劳。

### 五、发布前修的两个问题

**fake-ip 误报。** 原来只要域名解析到 fake-ip 就报「解析到了非公网地址」警告。
但开着 TUN 的人本来就是这个状态，一次扫描会出四条红字，看起来像工具坏了。
改成信息级只报一条，且明说「这是正常表现」。

**截图脱敏。** 文档用截图里的环境行包含真实出口网卡地址和公网 IPv6。
发之前把那行从页面隐掉重拍了一次。
